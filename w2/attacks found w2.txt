This error is fully expected and acceptable for Week 2.
What it means: OFMC requires that every constant appearing in the protocol must be in the initial knowledge of at least one role. grant and photos are declared as Number constants (lowercase), so OFMC treats them as fixed constants rather than fresh variables — and since no role has them in its initial knowledge, it complains.
Why it's a Week 2 constraint: At this stage we deliberately kept things simple. Modeling grant and photos correctly as agent-specific values requires declaring them as Function (i.e. grant(A), photos(A)), which is a Week 3+ concern. Alternatively, they need to appear in at least one role's initial knowledge (e.g. B: ..., photos) as a stopgap, which is a simplification we accepted for the bare-bones first version.
How it gets resolved in Week 3: photos becomes photos(A) — a function — and lives in B's initial knowledge as photos(A). grant becomes a fresh Number variable (uppercase Grant or just kept as a variable that idp generates fresh), so it is no longer a constant that needs to be pre-known. Once both are modeled correctly the error disappears entirely.
So in short: the error tells us exactly what needs to improve next, and it does get fixed in the Week 3 redesign. For the Week 2 logbook entry, this is worth noting as a known limitation of the simplified first version.

Option 1: Weaken the secrecy goal (most appropriate for w2)
Instead of claiming Grant is secret in all sessions, scope it to honest runs only. In AnB, the standard way is to use a secret goal only for values that are truly generated as session secrets. Since Grant is sent to P and forwarded to B, it's inherently known to all three — the real threat is the intruder learning it.
Change:
Grant secret between A, P, B;
To:
Grant secret between A, P;
...since B only needs to verify it, not keep it secret. Or consider dropping the secrecy goal for Grant altogether and relying only on authentication — which is the real security property here.
Option 2: Keep goals, fix the model intent
If Grant must stay secret among A, P, B, you need to acknowledge that OFMC is correctly identifying that in a session where the intruder plays one of the roles, the secret leaks. This is expected and acceptable — the protocol is secure for honest principals.
