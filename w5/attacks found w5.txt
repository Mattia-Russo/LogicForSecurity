WHY USING TWO DIFFERENT NONCE WHEN A REQUESTS TO IDP pk(P) and pk(B):
Technically, A could reuse na for both key lookups — but using two separate nonces na and nb is better practice for this reason:
Nonce reuse conflates two separate exchanges. If A sends na in both requests and idp echoes na back in both responses, 
A cannot cryptographically distinguish "this response is for my P-key request" from "this response is for my B-key request." 
An attacker who can replay idp's response to the first request could potentially substitute it as the response to the second, 
making A believe pk(P) is also the public key of B (or vice versa). By using distinct nonces na and nb, each response is bound 
to exactly one request, so A can be sure which key certificate answers which query.
